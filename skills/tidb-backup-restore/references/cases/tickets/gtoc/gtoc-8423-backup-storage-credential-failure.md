## Symptom / Description Excerpt

We've hit an issue in BR when using IRSA (AWS Web Identity / EKS Pod Identity) with a custom S3 endpoint override in a FedRAMP environment.  
**Issue**: In br/pkg/storage/s3.go → NewS3Storage(), when s3.endpoint is set, awsConfig.WithEndpoint() is called globally before session.NewSessionWithOptions(). This causes the AWS SDK's AssumeRoleWithWebIdentity credential chain to use the custom S3 endpoint as the STS endpoint, resulting in:  
**webIdentityErr**: failed to retrieve credentials  
caused by: SerializationError: failed to unmarshal error message, status code: 405  
**Root cause:** The same issue is documented in [aws-sdk-go#3972](https://github.com/aws/aws-sdk-go/issues/3972) and was already worked around in the tidb-operator's remote.go (with a comment explaining exactly this problem).  
**Proposed fix**: For Provider == "aws", skip setting the global endpoint before session creation, and instead set ses.Config.Endpoint after session.NewSessionWithOptions() — so IRSA credential resolution uses the real STS endpoint, while S3 API calls still use the custom endpoint.
