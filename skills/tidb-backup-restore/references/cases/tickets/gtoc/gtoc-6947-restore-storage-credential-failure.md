## Symptom / Description Excerpt

Hello we saw one dataplane backup job completed successfully without the backupmeta file. The backup log showed `nothing to backup` and completed directly instead of going through rest of the steps, like making backup meta and upload to S3. ([code](https://github.com/pingcap/tidb/blob/release-8.0/br/pkg/task/backup_ebs.go#L100)).  
We discovered this issue during the backup cleanup process. the cleanup got stuck due to the backup is not failed but doesn’t have a backupmeta. It blocked the whole clean schedule and needed a manual fix.

backup log: <custom data-type="smartlink" data-id="id-0">https://gist.github.com/olivia-chen-github/af5a8fbc0c81e0c941b94ef8d5a4e562</custom> 

In this case we think the cleanup process makes sense that this behavior is unexpected. But for the backup behavior, does it make sense to fail this backup if there’s no stores? Asking this bc even we make a backupmeta for no store condition(probably need more change), is this backup recoverable?

Another question is how do we count the store numbers? cause we don’t expect a count 0 here.
